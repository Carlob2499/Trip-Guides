### (C) Concrete Implementation and Interaction Guidance
*   **Looping Content:** Any animation repeating infinitely (carousels, background videos, looping illustrations) must have a visible control to stop it.
*   **Media Queries:** Use the CSS `@media (prefers-reduced-motion: reduce)` and JavaScript `window.matchMedia('(prefers-reduced-motion: reduce)')` to detect user intent.
*   **Substitution over Removal:** Instead of simply disabling motion, substitute high-motion triggers (zooms, slides) with safer non-motion transitions like cross-fades or opacity changes.
*   **Smart Toggles:** For high-motion experiences, provide a site-specific "Reduced Motion" toggle. It should check the OS preference first, allow user override, and persist the choice (e.g., via local storage).
*   **Subtle Cues:** Retain subtle animations like hover effects or small affordances even in "reduced" mode if they provide essential feedback without creating large-scale screen movement.

### (D) Tensions and Exceptions
*   **Essential Activity:** Motion is permitted if stopping it would break the core functionality (e.g., a game where movement is the primary interaction).
*   **Critical Information:** Exceptions exist for time-sensitive data, such as a live stock ticker, where stopping the motion would prevent the user from receiving necessary updates.
*   **Loading Indicators:** Spinners are generally exempt from the 5-second rule because they provide critical feedback that a process is still active.
*   **Color-Specific Thresholds:** Flashing the color red has a much stricter threshold than other colors due to its higher risk for triggering seizures.

### (E) Non-Authoritative Observations for Traveler PWAs
*   **Parallax Risks:** Parallax (multi-speed/multi-directional movement) is cited as a primary trigger for vestibular discomfort and should be avoided or strictly reduced for travelers who may already be in unstable environments (e.g., a moving train).
*   **Reading Interference:** Constant motion near static text (like animated pull-quotes) creates high cognitive load and distraction, making it difficult for users to focus on essential information.
*   **Subtle UI Motion:** Changes in color, blur, or opacity are generally considered safe and do not typically require reduction, as they do not create the "illusion of physical movement."
*   **User Expectations:** Motion toggles are becoming a standard feature for modern, inclusive web applications, moving beyond simple compliance into expected user control.
