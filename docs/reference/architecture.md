# Architecture — Waypoint Travel Guides

Developer/agent orientation. The working rules (ship loop, continuity sweep, accuracy
standards) live in the auto-loaded `CLAUDE.md` (project) stacked on `~/.claude/CLAUDE.md`
(accuracy); content-authoring standards live in the `waypoint-guide-author` skill. This
file is durable architecture only — for the exact current shape prefer `git log` and the
`src/` tree over prose.

**Repo:** github.com/Carlob2499/Trip-Guides · **Live:** carlob2499.github.io/Trip-Guides/

## What it is

A static **Astro** site of curated, fact-checked, personalized travel guides — never
autogenerated from training data (see `CLAUDE.md` for the 4-property bar). The owner is
not a programmer: edit JSON → push → GitHub Actions rebuilds and deploys to GitHub Pages.
Published guides: **Japan**, **Sedona** (current) · **South Korea**, **Denmark** (`archived:
true` — concluded trips, kept as the historical record).

**Stack:** Astro (static) · JSON content in `src/content/guides/` (validated by a Zod
discriminated union in `src/content.config.ts`) · per-feature CSS in `src/styles/` +
client modules in `src/scripts/` · self-contained features in `src/features/<name>/`
(Firebase live-sync is the reference) · GitHub Pages (base `/Trip-Guides`) · PWA (offline
via `public/sw.js`) · CI in `.github/workflows/`.

**Maps:** OpenStreetMap iframe by default; the Google renderer (`gmaps-render.js`)
self-boots to upgrade it only when `PUBLIC_GMAPS_KEY` is set.

## File map

- `src/content/guides/<slug>/` — the guides (the only per-country files): `_guide.json`
  meta + `NN-<group>.json` per tab group + `facts.json` (the perishable-fact registry),
  assembled by the loader. ONE shape, gated by `guide-shape-uniform.test.mjs` — a flat
  `<slug>.json` fails the suite (it also silently shadows a directory of the same slug).
  Split an imported single-file guide with `npm run split-guide -- <slug>`.
- `src/lib/facts.mjs` — the fact-registry mechanics: `isSectionFile` (the canonical
  guide-directory filter every reader shares) and `{{fact:id}}` interpolation, applied by
  the loader AND by `scripts/audit/lib.mjs` so the site and the gates never disagree.
- `src/lib/modify-schema.mjs` — single source for the "Request a change" intake (fields,
  prefill URL, section sanitiser); the modify-side twin of `scripts/intake-schema.mjs`.
- `src/content.config.ts` — the section schema (discriminated union of block types) plus
  the `facts.json` record shape.
- `worker/` — the Cloudflare Worker that files a new-guide issue for an anonymous visitor
  (config-gated; the site falls back to a prefilled-issue link when it's off).
- `src/layouts/GuideLayout.astro` — the guide shell; imports styles + client modules.
  `src/components/blocks/*.astro` — one renderer per section type, dispatched by `Block.astro`.
- `src/pages/index.astro` — the hub (verified guides only). `og/[slug].png.ts`,
  `guides/[slug].gpx.ts`, `.ics.ts` — build-time generated assets per guide.
- `src/data/countries.mjs` — single source for accent / currency / IANA tz / ISO / capital /
  emergency numbers (imported by both TS and Node scripts).
- `src/lib/` — pure build-time helpers (exports, holidays, map-pins, themes, settle) + tests.
- `src/features/<name>/` — self-contained features (sealed dir, single `index.ts` public API).
- `scripts/` — guide scaffolding (`scaffold-guide.mjs`), the research self-correction
  gate (`guide-readiness.mjs` → `npm run readiness`), enrichers
  (`lookup-place`, `search-commons`, `fetch-wikivoyage`), the weekly content audit
  (`audit/*`), and the new-guide scaffold.
- `.claude/skills/waypoint-guide-author/` — the content-authoring skill (verification and
  writing standards live here, not in this doc).

## Architecture decisions (the durable ones)

- **JSON, not a CMS/MDX** — the owner edits data, not markup; the schema is the guardrail.
- **Shared components are global; only JSON is per-country** — a component change hits every
  guide at once (intended).
- **New feature = its own folder** — `src/features/<name>/` with a single `index.ts`/`index.js`
  API; third-party SDKs behind a config gate + lazy import (Firebase / Google Maps are the
  pattern). **The silo contract** (the original migration is long complete; 22 silos today, and
  this is the standing rule for new ones — formerly a standalone roadmap doc): the index file is
  the ONLY public surface (no deep cross-feature imports, ever) · `model/` = zod + pure tested
  logic · `ui/` · `mocks/`
  (real-shaped seeds; tests run zero-network) · `__tests__/`. Data access sits behind an
  injectable gateway in `index.ts` (backend-ready). Lazy: a feature is its own `import()`
  chunk. No speculative silos. **Feature CSS** is a per-silo call: page-chrome styling that
  isn't really "one feature's" (masthead, tabs, print rules, …) stays centralized in
  `src/styles/` — Astro bundles all imported sheets per-page anyway, and GuideLayout's single
  ordered import list IS the cascade contract. A feature with its OWN self-contained styling
  (firebase, trip-kit, learnings, reminders are the shipped examples) instead ships a
  **`styles.css` at the silo's ROOT** (sibling to `index.ts`, never under `ui/`) — the
  consumer imports `features/<name>/styles.css`, one hop below the silo boundary, same as
  importing the silo's `index.ts` itself; never a deeper path like `ui/<name>.css` (A1 — that
  was a real bug: 4 components were doing exactly that, reaching past the silo boundary to
  style a feature they don't own). Cross-cutting page chrome (guide-ui, scroll-memory,
  reveal, lightbox, …) stays flat in `src/scripts/` — it is the page, not a feature.
- **Exports are build-time endpoints** (`getStaticPaths` + GET), mirroring the OG image — no
  separate pre-build step, no runtime.
- **Base-path hrefs are explicit** — every internal `/`-href uses `import.meta.env.BASE_URL`.
- **Live data degrades gracefully** — currency/weather/holidays fetch-once, cache, and hide or
  fall back on failure; never break the page.
- **JSON encoding** — guide files are UTF-8; keep native-script text and `≈`/`⚠` glyphs intact.
  On Windows, `PYTHONUTF8=1` for any Python touching them.

## How to work with it

- **Content change:** edit the guide JSON, then run the continuity sweep + ship loop from
  `CLAUDE.md`. Fact edits follow the `waypoint-guide-author` skill.
- **New country:** add a row to `src/data/countries.mjs`, then scaffold/author (intake:
  `docs/standards/new-guide-intake.md`).
- **New section type:** add a Zod member to `src/content.config.ts`, a renderer in
  `src/components/blocks/`, and wire it in `Block.astro`.
- **New styling:** three gates run on every stylesheet and each catches a class of bug the
  others cannot. `src/styles/var-defined.test.ts` fails a `var()` that nothing declares (CSS
  does not error on those — the declaration is invalid at computed-value time and silently
  falls back). `src/styles/type-scale.test.ts` fails a raw `font-size` outside the scale.
  `src/styles/atlas-tokens.test.ts` pins the contrast contracts, including the four ink-on-fill
  tokens that must NOT re-map (`--on-aink`, `--on-accent`, `--crit-fill`, `--on-crit`) and the
  two that MUST (`--on-green`, `--cta`/`--cta-ink`). Reach for a token before a literal: ink on
  a coloured FILL is never `--accent-ink`/`--ink`, it is the `--on-*` of that fill.
