# Motion & Navigation Anchors (internal reference)

Curated inspiration anchors for Waypoint motion work. Target feel: fast (150–350ms core UI, longer only for geographic camera moves), smooth, interruptible, Airbnb-warm — never rigid/enterprise. Researched 2026-08-28; links may rot, the technique note is the durable part.

## A. Geographic / globe fly-to & map navigation

- **Mapbox Storytelling template** — the canonical "waypoint" grammar: sticky full-bleed map, prose chapters trigger `flyTo` per chapter (center/zoom/pitch/bearing per step, IntersectionObserver + Scrollama). Steal the chaptered fly-to structure and per-chapter camera options. https://labs.mapbox.com/scrollytelling/scrollytelling.html and https://www.mapbox.com/blog/interactive-storytelling-3d-maps-with-mapbox-gl-js-v2
- **Mapbox GL `flyTo` easing docs** — the arc of a good fly-to: zoom out, translate, zoom in (van Wijk & Nuij curve); tune `curve`/`speed` rather than duration so long hops don't drag. https://docs.mapbox.com/mapbox-gl-js/example/flyto-options/ and scroll-driven variant https://docs.mapbox.com/mapbox-gl-js/example/scroll-fly-to/
- **Google Earth Studio easing + camera target** — cinematic reference for geographic arrival: drone-like deceleration into a point of interest, camera locked on a target while translating; steal the "ease on speed curves, not value curves" idea for fly-to feel. https://earth.google.com/studio/docs/making-animations/easing/
- **GitHub globe (how-we-built-it)** — lightweight, textureless dot-globe with graceful degradation per device; steal the layered build (halo, dots, arcs) and the frame-rate-first fallback discipline. https://github.blog/engineering/engineering-principles/how-we-built-the-github-globe/
- **Stripe interactive globe** — restrained, brand-warm globe as ambient context rather than toy; slow idle rotation, instant response to input. https://stripe.com/blog/globe
- **Igloo Inc (Awwwards Site of the Year 2024)** — camera *drifts* between scenes with soft dissolves instead of hard cuts; steal the continuous-camera-as-navigation idea for section changes. https://www.webgpu.com/showcase/igloo-inc-procedural-crystals/

## B. Page / shared-element transitions

- **Airbnb "Motion engineering at scale"** — declarative shared-element transitions between screens to preserve context; the card→detail morph is the anchor pattern for guide card → guide page. https://medium.com/airbnb-engineering/motion-engineering-at-scale-5ffabfc878
- **Airbnb Host Passport animation** — synced snapshot + transition so the shared element never pops; steal the "everything moves together or not at all" discipline. https://medium.com/airbnb-engineering/animations-bringing-the-host-passport-to-life-on-ios-72856aea68a7
- **Maxi Ferreira's Astro shared-element experiments** — movie-card → detail morph in Astro specifically, incl. persisted media across navigations; closest existing analog to what Waypoint should do. https://www.maxiferreira.com/blog/astro-page-transitions/ (code: https://github.com/Charca/astro-movies)
- **Bramus's View Transitions demo hub** — list→detail, gallery, persisted player demos with real timings; the reference implementations to copy timings from (most run ~250ms). https://view-transitions.chrome.dev/
- **Orpetron page-transition roundups** — periodic curated lists of award sites doing transitions well; use as a refresh source, not a one-time read. https://orpetron.com/blog/10-award-winning-websites-mastering-the-art-of-page-transitions/
- **Lusion (Awwwards/FWA Site of the Year)** — the high end of fluid WebGL transitions; steal the pacing (fast response, long soft settle), not the spectacle. https://lusion.co (case study: https://www.awwwards.com/case-study-for-lusion-by-lusion-winner-of-site-of-the-month-may.html)

## C. Scroll & reveal (desktop)

- **NYT "Snow Fall" / "The Russia Left Behind"** — full-bleed media pinned while prose scrolls over it; in the Russia piece, scrolling down *is* traveling down the highway — the scroll-as-journey metaphor Waypoint's itinerary pages can borrow directly. Canon overview: https://scrollytelling.ai/famous-scrollytelling-examples/
- **Shorthand scrollytelling roundup** — 12 curated scroll-driven stories; good for chapter/title-card rhythm (each section opens on a visual behaving like a title card). https://shorthand.com/the-craft/scrollytelling-examples/
- **Codrops camera fly-through on scroll (Theatre.js + R3F)** — scroll position drives a pre-authored camera path; the technique behind "flying into" a destination on scroll, interruptible by definition because scroll owns the timeline. https://tympanus.net/codrops/2023/02/14/animate-a-camera-fly-through-on-scroll-using-theatre-js-and-react-three-fiber/
- **D3 scrollytelling globe (Storybench)** — globe that flies from flight-path close-up to global view purely on scroll; a lighter-weight globe grammar than Mapbox. https://www.storybench.org/from-csv-to-spinning-sphere-how-to-build-a-scrollytelling-globe-with-d3-js/
- **Linear / Stripe marketing sites** — the "fast and quiet" end: reveals are short, small-distance, opacity+translate, never blocking scroll; steal the restraint as the default register for non-hero surfaces.

## D. Mobile gesture-driven fluid navigation

- **Apple HIG / "Building Fluid Interfaces" (Nathan Gitter, from Apple's WWDC18 talk)** — the doctrine: motion starts from the current value, inherits gesture velocity, projects momentum, and is grabbable/reversible at any instant. Springs (stiffness/damping), not fixed-duration curves, for anything a finger drives. https://medium.com/@nathangitter/building-fluid-interfaces-ios-swift-9732bb934bf5
- **Apple Maps bottom sheet with detents** — the map-app navigation anchor: content sheet over a persistent map, three detents, drag interruptible anywhere mid-flight; Waypoint's mobile map/list split should feel like this. Web/Expo recreation: https://expo.dev/blog/how-to-create-apple-maps-style-liquid-glass-sheets
- **Airbnb app map↔list morph** — search results and map are one surface; toggling animates shared pins/cards rather than swapping screens. (No single URL; observe the app. Lottie post for their motion tooling: https://medium.com/airbnb-engineering/introducing-lottie-4ff4a0afac0e)
- **iOS edge-swipe back** — the interruptibility bar to meet on web: transition tracks the finger 1:1 and can be abandoned mid-gesture. Desktop and mobile keep a *related* grammar by sharing the same shared-element morphs — desktop triggers them by click, mobile by gesture — so the spatial model is identical, only the input differs.

## E. Implementation notes for Astro

- **Astro `<ClientRouter />` view transitions**: `transition:name` pairs elements across routes (guide card image → guide hero), `transition:persist` keeps a live component (the map!) mounted across navigations — a persisted Mapbox/MapLibre instance plus `flyTo` on route change gives the geographic fly-to *as* the page transition. Docs: https://docs.astro.build/en/guides/view-transitions/ ; background: https://developer.chrome.com/blog/astro-view-transitions ; Astro is also moving toward zero-JS native cross-document view transitions (https://astro.build/blog/future-of-astro-zero-js-view-transitions/) — prefer CSS-only `@view-transition` where the JS router isn't otherwise needed.
- **Timing defaults**: default view-transition is ~300ms crossfade; override per-element with `::view-transition-old/new(name)` CSS. Keep shared-element morphs 200–300ms with a standard ease-out; reserve 600–1200ms only for map camera fly-tos, which read as travel, not lag. `view-transition-name` must be unique per rendered page — beware repeated guide cards (derive the name from the slug).
- **Lenis-style smooth scroll vs "never hijack scroll"**: Lenis/virtual-scroll re-times the user's wheel input — that *is* scroll hijacking and conflicts with the repo's rule and with assistive tech (see https://frontendchecklist.io/rules/accessibility/scrolljacking, https://css-tricks.com/smooth-scrolling-accessibility/). The award-site feel is achievable without it: use native scroll + CSS scroll-driven animations / IntersectionObserver for reveals, and let *cameras* (map, WebGL) interpolate smoothly toward native scroll position — smooth the output, never the input. If any smoothing or `scroll-behavior: smooth` is used, gate it behind `prefers-reduced-motion: no-preference`.
- **Reduced motion & fallback**: every transition needs a reduced-motion branch (crossfade or none) and the site must be fully navigable where view transitions are unsupported (they are progressive enhancement by design). Map fly-tos degrade to `jumpTo` under reduced motion — Mapbox honors this only if you wire it.
- **Gesture surfaces**: for any web bottom-sheet/drawer, follow the fluid-interface doctrine above — pointer-driven position, spring settle (e.g. CSS `linear()` spring or a small physics lib), interruptible mid-flight; avoid fixed-duration CSS transitions on anything a finger drags.
