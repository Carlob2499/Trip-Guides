## Critical correction

The September mockup library is the **visual ancestry** of the final redesign.

Do not interpret the constitution as permission to invent a new aesthetic from prose.
The correct transformation is:

> **approved mockup composition + only the later explicit UX/product changes = final Waypoint**

The result should look like the same product matured, not a different app using similar colors.

Preserve from the strongest mockups unless a later decision directly conflicts:
- destination photography as structural UI;
- globe/map as major visual anchors;
- warm ivory/editorial surfaces paired with deep navy/forest spatial surfaces;
- rust/orange action and selection emphasis;
- Literata-like editorial scale + hyperlegible operational sans;
- useful desktop density;
- purposeful overlap, layering, translucency, and depth;
- rich map/place relationships;
- mobile compositions designed independently rather than shrunk from desktop;
- topographic/cartographic texture;
- strong country/Guide identity.

Explicit later changes still apply, including:
- adaptive floating desktop navigation;
- five core mobile destinations;
- Split contextual;
- Search global/context-aware;
- SOS globally available layered tool;
- Google Maps Platform underneath Waypoint's map experience;
- fluid panes and shared-object continuity;
- branching New Guide question cards;
- cream/sage/rust/charcoal final palette where older boards conflict;
- invisible AI.

## New feature rule

For features decided after the mockup library — such as the adaptive Guide-creation question deck,
card stack/unfold choreography, pin-to-compare, and final fluid-pane behavior — extend the mockup
visual grammar.

A new screen should look as though it could have been another polished board in the same library.
Do not solve new features by falling back to generic SaaS composition.

## Cohesion / lineage acceptance

For each flagship implementation screenshot, compare it side by side with its relevant approved
mockup(s).

Pass only when both statements are true:

1. **The explicit final UX decisions are present.**
2. **The screen is immediately recognizable as an evolution of the approved Waypoint mockups.**

If the implementation is technically compliant with the constitution but visually resembles a new
unrelated app, it fails D7 visual acceptance.
